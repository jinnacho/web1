Chapter 12: 최종 테스트하고 재배포하기¶

🎯 이 장에서 배우는 것¶

  • 학생용 신청과 교사용 관리 기능을 시나리오별로 전체 테스트할 수 있다
  • 발견된 문제를 AI Studio Build에 설명하여 수정할 수 있다
  • 수정된 앱을 firebase deploy로 재배포할 수 있다

📚 핵심 개념¶

개념: 시나리오 테스트¶

"시나리오 테스트는 마치 연극 리허설과 같아요. 본 공연(실제 사용) 전에 처음부터 끝까지 대본대로 해보면서 문제가 없는지 확인하는 거예요."

정확한 정의: 사용자가 실제로 앱을 쓰는 순서대로 기능을 하나씩 실행하며, 오류 없이 동작하는지 점검하는 과정입니다.

왜 중요할까요? 개별 기능은 잘 되더라도 전체 흐름으로 연결했을 때 문제가 생길 수 있습니다. 예를 들어 신청은 되는데 명단에 안 뜨거나, 삭제 후 화면이 안 바뀌거나 하는 경우죠.

🔨 따라하기¶

Step 1: 시나리오대로 전체 테스트하기¶

로컬 서버(firebase emulators:start 또는 npm run dev)를 실행한 뒤, 아래 순서대로 직접 해보세요.

🧑‍🎓 학생 역할 테스트 1. 학생 신청 페이지에서 이름·학번 등 입력 후 신청 버튼 클릭 2. 신청 완료 메시지가 정상적으로 표시되는지 확인 3. 같은 정보로 중복 신청을 시도해보기 (막혀야 정상!)

🧑‍🏫 교사 역할 테스트 1. 교사 관리 페이지에서 명단 조회 → 방금 신청한 학생이 보이는지 확인 2. 해당 학생 정보를 수정하고 저장 → 변경 내용이 반영되는지 확인 3. CSV 다운로드 → 파일이 정상적으로 받아지는지 확인 4. 학생 한 명을 삭제 → 목록에서 사라지는지 확인

💡 팁: 테스트할 때 메모장이나 체크리스트를 옆에 두고 결과를 적으면 놓치는 게 없어요!

Step 2: 문제 발견 시 AI로 디버깅하기¶

테스트 중 오류를 발견했다면, AI Studio Build에 상황을 설명하세요.

좋은 프롬프트 예시:

CSV 다운로드 버튼을 클릭하면 파일은 받아지는데,
한글 이름이 깨져서 나옵니다.
현재 다운로드 함수는 아래와 같습니다:
[해당 코드 붙여넣기]
한글이 정상 출력되도록 수정해주세요.

핵심 포인트 3가지: - 뭘 했는지 (어떤 버튼을 클릭) - 뭐가 잘못됐는지 (한글 깨짐) - 현재 코드 (관련 부분 복사)

AI가 수정 코드를 주면, 해당 부분만 교체하고 다시 테스트합니다. ✅ 통과하면 다음 단계로!

Step 3: 재배포하기¶

모든 테스트를 통과했으면 최종 배포합니다.

firebase deploy

실행 결과: 

✔ Deploy complete!

Hosting URL: https://your-project.web.app

표시된 URL에 접속해서 Step 1의 시나리오를 한 번 더 간단히 확인하세요. 로컬에서는 됐는데 배포 후 안 되는 경우가 가끔 있거든요! 🔍

⚠️ 주의할 점¶

  1. 배포 전 반드시 빌드 확인: 프레임워크를 사용 중이라면 npm run build가 에러 없이 완료된 후 firebase deploy를 실행하세요.
  2. 브라우저 캐시 주의: 재배포 후 변경이 안 보이면 Ctrl + Shift + R(강력 새로고침)을 눌러보세요.

✅ 점검하기¶

1. 시나리오 테스트에서 가장 중요한 것은?

정답 확인개별 기능이 아니라, 사용자가 실제로 쓰는 순서(전체 흐름)대로 테스트하는 것입니다.

2. AI에게 오류 수정을 요청할 때 꼭 포함해야 할 3가지는?

정답 확인① 뭘 했는지(조작 과정) ② 뭐가 잘못됐는지(증상) ③ 현재 코드(관련 부분)입니다.

3. 재배포 후 화면이 안 바뀌면 어떻게 해야 하나요?

정답 확인Ctrl + Shift + R로 브라우저 강력 새로고침을 합니다. 캐시된 이전 버전이 보이고 있을 수 있습니다.
